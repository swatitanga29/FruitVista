    Table and schema used

    The import reuses the existing daily_records table - no duplicate table and no duplicate column was added. Import runs are recorded separately in import_batches.

    • Table: daily_records - one row per day, district and fruit.
    • Distinguisher: record_source is 'historical' for this dataset and 'manual' for entries made in the Sales Entry page.
    • Duplicate key: UNIQUE (record_date, district_id, fruit_id, record_source), combined with INSERT OR IGNORE.
    • Import tracking: import_batches stores the file name, its hash, the row counters and the run status.
    • Safety: existing rows are only ever read. The import never updates, deletes or overwrites a record, and every slice runs inside a transaction that is rolled back on failure.

    How to verify the imported records

    Open a terminal in the FruitVista folder, activate the virtual environment and start a SQLite session. 

    .\.venv\Scripts\python -c "import sqlite3; db = sqlite3.connect('database/fruitvista.db'); print(db.execute(\"SELECT COUNT(*) FROM daily_records WHERE record_source = 'historical'\").fetchone()[0]); print(db.execute(\"SELECT COUNT(*) FROM daily_records WHERE record_source = 'manual'\").fetchone()[0])"
    • The first number is the historical row count and should match Successfully imported above (plus any earlier completed import).
    • The second number is the manual row count. It must be unchanged by the import.
    • Re-running the import must report 0 imported and every row as a duplicate - proof that no row was written twice.
    • The Recent import runs table above and the import_batches table both keep a permanent record of each run.
